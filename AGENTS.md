# AGENTS.md — read this first

You are an AI agent. Someone pointed you at **visual-lab**: a library of **HTML/CSS layout
patterns** reverse-engineered from real designs, each one themable by CSS variables and each one
backed by **measurable geometry assertions**. Use it so you stop reinventing a KPI card, a nav
bar or a heatmap from scratch every time.

Nothing to install. No network. No build step. `git clone`, then read on.

---

## 60 seconds

```bash
node bin/index.mjs                                  # rebuild the catalogue + the gallery
sed -n "/## Catalogue/,/## Détail/p" INDEX.md        # one line per pattern — route from here
node bin/search.mjs "kpi row"                        # full-text (OR, ranked)
node bin/search.mjs --show card-12-inverted-kpi-row  # the fragment + its :root, ready to paste
open gallery.html                                    # every pattern RENDERED, filterable
```

`gallery.html` is the human view: live fragments, a corpus map (references × families, so the
gaps are visible), text search, family/media filters, and a copy button per pattern. It is
regenerated by `bin/index.mjs` — never edit it.

**To propose a shortlist** — before building a page or a deck, put the finalists in front of
whoever decides, as a page they open rather than a paragraph they read:

```bash
node bin/gallery.mjs card-12-inverted-kpi-row chart-05-tile-heatmap --out /tmp/proposal.html
```

Any mix of pattern ids and reference prefixes works. `--out` is **required** for a filtered
selection: a partial board written over `gallery.html` would replace the library index with a
subset, and the next person to open it would think the repo had emptied. External boards get
absolute font and deck links, so they render standalone.

**Requirements**: Node ≥ 18 for everything above. Google Chrome only for the *verification*
tools (`bin/check.mjs`, `bin/check-deck.mjs`, `bin/render.mjs`), which you do not need in order
to consume a pattern.

## What a pattern is

A pattern is **exactly two files**, and nothing else:

| file | what it holds |
|---|---|
| `patterns/<id>.json` | intent, `when_to_use`, `avoid_when`, tags, CSS variables, **ratios**, **benchmarks** |
| `patterns/<id>.html` | a self-contained fragment: markup + its own `<style>`, colours only via `var(--vl-*)` |

Two more directories complete it:

- `systems/<ref>.json` — the **tokens** of one design system (palette, type scale, radii). The
  system carries the scale and the palette; the fragment never does.
- `decks/<ref>.html` — the full screen or slide the pattern was extracted from, rebuilt.

Naming is the taxonomy, there is no second field that could contradict it:
`<family>[-NN]-<words>` for a pattern, `ref-NN-<slug>` for a reference. Families are a **closed
vocabulary**: `card`, `chart`, `diagram`, `layout`, `list`, `shape`, `tag`, `title`. A `chart`
carries DATA (a measured value decides the geometry); a `diagram` carries STRUCTURE (nothing is
proportional to anything).

## How to consume it programmatically

`index.json` is the machine view — generated, versioned, never hand-edited:

```jsonc
{
  "counts":   { "patterns": 38, "refs": 15, "checkable": 31 },
  "families": ["card", "chart", "diagram", "layout", "list", "shape", "tag", "title"],
  "media":    ["slide", "web", "email", "print", "social"],
  "patterns": [{
    "id": "card-12-inverted-kpi-row",
    "family": "card",
    "ref": "ref-18-lime-sales-dashboard",   // → systems/<ref>.json for the tokens
    "intent": "…", "when_to_use": "…", "avoid_when": "…",
    "media": ["web", "slide"],
    "vars": [{ "name": "--vl-invert", "role": "…", "default": "#000000" }],
    "geometry": { "root": ".vl-kpirow", "frame": [1286, 219], "ratios": { … } },
    "benchmarks": [{ "name": "…", "measure": "<JS expression>", "expect": 1.05, "tol": 0.03 }]
  }],
  "refs": [{ "id": "ref-18-…", "tokens": { "--vl-accent": "#5FE85C", … }, "type": { … } }]
}
```

Pick on `intent` / `when_to_use` / `tags`; **respect `avoid_when`** — it is the field that stops
you shipping a pattern in the one situation where it hurts.

## How to use a pattern

1. Paste the `<style>`-carrying fragment where you need it.
2. Paste the `:root` of its reference — or map `--vl-*` onto your own design tokens. Every
   colour, radius and gap is a variable; there is not one hardcoded hex below `:root`. Check
   your mapping with `node bin/emit.mjs <id> --target inline --system <other-ref>`: an
   unresolved variable is reported, never silently rendered grey.
3. Replace the demo copy. It uses the fictional name `northbeam` on purpose — real brand names
   in filler text get shipped by whoever pastes next.

## How to verify what you built

```bash
node bin/check.mjs <id>          # runs the pattern's benchmarks in real Chrome, exits 1 on failure
node bin/check-deck.mjs <ref>    # the COMPOSITION: stage format, layer depth, redundant 1:1 layer
node bin/emit.mjs --audit --target email    # what actually survives an email client
```

Benchmarks are the point of this repo. They are JS expressions measured in a real browser after
layout (`box()`, `num()`, `cs()`, `contrast()`, `overflow()`, …), written as **ratios of the
pattern root** so they survive a change of scale. A pattern with no measurable assertion is a
screenshot with words around it.

If you add or modify a pattern, add benchmarks. `bin/index.mjs` refuses to index a pattern that
breaks the contract (unknown family, hardcoded colour, missing `geometry.root`).

## Do not

- **Do not edit generated files**: `INDEX.md`, `index.json`, `gallery.html`, `patterns.db`.
  Regenerate with `node bin/index.mjs`. The disk (`patterns/`, `systems/`) is the truth.
- **Do not hardcode a colour** in a fragment — the indexer rejects it, on purpose.
- **Do not ship a PNG of a pattern.** An image is a dead copy: it goes stale silently, cannot be
  zoomed, inspected or copied. Serve `gallery.html` or the deck. Rasters live in `proofs/`,
  gitignored, as a measuring instrument only.
- **Do not treat the demo copy as content.** See point 3 above.

## Two files here are the maintainer's own, not yours

`SKILL.md` is the maintainer's operator manual (in French, written for their own agent setup) and
`ROADMAP.md` is their work log. They are worth reading for the *reasoning* — every trap paid for
is written down there — but nothing in them is required to use the library. Start here, then
[`README.md`](README.md) for the architecture and [`DOCTRINE.md`](DOCTRINE.md) for the layout
laws the whole corpus obeys.

The pattern notes are in French. They are the most valuable text in the repo — each one records
why a composition works and which control caught which defect. Translate on the fly if needed;
do not strip them.
